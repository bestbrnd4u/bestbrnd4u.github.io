# Відгуки покупців

І зірки в пошуку, які без них не з'являться.

## Навіщо

У 73 товарах зі 100 стоїть рейтинг, а відгуків немає **ні в одного**.
Тому розмітка для Google свідомо ховає `aggregateRating`: рейтинг без
жодного відгуку — пряма причина ручних санкцій, і краще не мати зірок,
ніж мати вигадані.

Наслідок: у пошуку немає зірок ні в кого. А зірки в сніпеті — це
приріст кліків на тій самій позиції, без жодних грошей за рекламу.

І друге, важливіше за SEO. На полиці 3 000–15 000 ₴ із логотипами
Gucci й Prada головне заперечення покупця — **«чи це не підробка»**.
Відгук іншого покупця відповідає на це переконливіше, ніж будь-який
текст магазину.

## Як це працює

### Відгук лише від того, хто купував

Форма просить **номер замовлення й телефон**. Сервер звіряє три речі:

1. замовлення з таким номером існує;
2. телефон збігається (останні 9 цифр — як на сторінці «Де моє
   замовлення»);
3. **цей товар справді був у його складі.**

Третя перевірка не менш важлива за другу: без неї той, хто купив
гаманець за 3 800, написав би відгук про сумку за 15 000 — номер і
телефон у нього справжні.

Перевіряє **функція службовим ключем**, не браузер: у браузері будь-яка
така перевірка нічого не варта, бо код сторінки відкритий, а запит можна
надіслати й без сторінки. Тому таблиця відгуків закрита від браузера
повністю (RLS без політик), а пише в неї функція — після перевірки.

**Відповідь на всі «не зійшлось» однакова.** Інакше форма стала б
способом дізнатись, що людина купувала.

### Відгук не з'являється сам

Кожен проходить модерацію. Одразу після надсилання вам у Telegram
приходить картка:

```
💬 Новий відгук ★★★★★

Шкіряна сумочка Coach Tabby 26

Сумка саме така, як на фото. Шкіра щільна…

👤 Ірина
🧾 замовлення 4821507392

[✅ Показати на сайті]  [🚫 Відхилити]
```

Натиснули — кнопки зникають, а в саме повідомлення дописується рішення.
Через тиждень буде видно, що ви з цим відгуком зробили.

Номер замовлення в картці не для краси: якщо відгук виглядає дивно,
за ним можна подивитись саму покупку.

⚠️ **Поки ви не натиснули, відгук не видно ніде.** Відгук, який
публікується автоматично, рано чи пізно принесе або спам, або чужу
лайку.

### Зірки в пошуку вмикаються самі

Нічого перемикати не треба. Розмітка вже вміє `aggregateRating` і
показує його, щойно `reviews > 0`.

Ланцюжок такий: `pull-reviews.js` читає зведення з бази → кладе в
`data/reviews.json` → `build-products.js` переносить числа в товар →
`product.js` будує розмітку. Крок стоїть у збірці **до** складання
товарів.

Числа з бази **переважають** ручний рейтинг: саме тому 73 заповнені
руками рейтинги не завадять.

### Прохання написати відгук

Через **тиждень** після статусу «Виконано» покупцеві йде лист із
фото товарів і посиланням на сторінку кожного — з уже підставленим
номером замовлення, щоб лишилось ввести телефон.

Раніше писати немає сенсу: людина ще не отримала посилку. Пізніше —
покупка забулась, і лист виглядає як реклама.

**Двічі не напишемо.** Таблиця `review_requests` пам'ятає, кому вже
писали, а позначка ставиться **лише після успішної відправки**: збій
пошти не має викидати людину з переліку назавжди. І не пишемо тому, хто
вже написав.

## Що зробити один раз

### Крок 1. Міграції

**Supabase → SQL Editor → New query**, по черзі:

1. `supabase/migrations/018-issue-kinds.sql`
2. `supabase/migrations/019-reviews.sql`

Перша розширює журнал подій (заодно виправляє те, що серверні
конверсії Meta мовчки не записувались — див. коментар у файлі). Друга
створює саму таблицю відгуків.

### Крок 2. Перезалити функцію

`supabase/functions/telegram-order-bot/index.ts` →
**Supabase → Edge Functions → telegram-order-bot** → **Deploy**.

Без цього форма відповість «не вдалося надіслати відгук».

### Крок 3. Перенести в main

**Actions → Sync branches → dev-to-main.** GitHub бере розклад тільки з
головної гілки, тож прохання про відгуки (`Request reviews`) без цього
не запускаються.

## Як перевірити, що працює

1. Оформіть тестове замовлення й доведіть його до «Виконано».
2. Відкрийте сторінку купленого товару → **Написати відгук**.
3. Введіть номер замовлення й той самий телефон.
4. У Telegram має прийти картка з кнопками.
5. Натисніть **Показати на сайті** → оновіть сторінку товару.

Зірки в розмітці з'являться після наступної збірки: перевірити можна в
`data/reviews.json` або так —

```bash
node scripts/pull-reviews.js --dry-run
```

Прохання про відгуки — без відправки:

```bash
node scripts/request-reviews.js --dry-run
```

### Опублікувати руками

Якщо кнопки в Telegram недоступні:

```sql
select id, author, rating, body from public.reviews where status = 'new';
update public.reviews set status = 'published' where id = 1;
```

### Відповісти на відгук

Відповідь показується під відгуком і робить більше, ніж будь-який
рекламний рядок: видно, що відгуки читають.

```sql
update public.reviews set reply = 'Дякуємо! Раді, що підійшла.' where id = 1;
```
