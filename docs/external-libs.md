# Зовнішні бібліотеки

Дві бібліотеки, від яких залежить магазин, **лежать у репозиторії**
(`assets/js/vendor/`). Три адмінські й далі підключаються з CDN.
**Усі версії закріплені точно** — без діапазонів на кшталт `@2`
чи `^3.0.0`.

## Чому свої, а не з CDN (03.11.2026)

Точна версія в адресі CDN — це обіцянка CDN, а не факт. Заміряно: те,
що `jsdelivr` віддає за `@2.112.3`, **не збігається байт-у-байт** із
пакетом тієї самої версії в npm (207,2 проти 206,9 КБ). Артефакт там
свій, і ніщо не заважає йому змінитись.

З тієї ж причини сюди не підходить і SRI: контрольна сума зламалася б
від будь-якої їхньої переобробки, і магазин лишився б без клієнта
Supabase.

Друга причина — швидкість. Заміряно, медіана з п'яти холодних
з'єднань: до `cdn.jsdelivr.net` TCP 44 мс, TLS 90 мс, перший байт
129 мс. Поки клієнт не приїде, не почнеться ні запит залишків, ні
відгуки, ні оформлення.

По дроту вага та сама — 53 КБ gzip. Виграш у тому, що байти віддає
той самий сервер, що й решту сайту, і що вони незмінні.

Кладе їх `npm run vendor` (`scripts/vendor-libs.js`). Він же
переписує теги на всіх сторінках, тож версія в імені файлу й в
адресі ніколи не розходяться.

## Чому закріплені

Раніше `supabase-js` підключався як `@supabase/supabase-js@2` — тобто
«будь-яка версія 2.x». CDN віддає найсвіжішу, і бібліотека
оновлювалась сама, без жодних змін у репозиторії.

Одне таке оновлення змінило склад подій авторизації: `SIGNED_IN`
почав приходити не лише при справжньому вході, а й при поновленні
токена. Кошик, який об'єднувався з акаунтом на цю подію, став
подвоюватись — у постраждалих доходило до 131072 одиниць одного
товару (2¹⁷, тобто 17 подій).

Причину того збою виправлено окремо (логіка більше не залежить від
типу події), але сам ризик лишався: будь-яка бібліотека могла
змінити поведінку в будь-який момент, а зміну неможливо ні
відтворити, ні відкотити — у репозиторії ж нічого не змінювалось.

Закріплені версії означають: сайт поводиться однаково сьогодні й
через півроку, а будь-яка зміна поведінки — це свідома правка з
історією в git.

## Що і де підключено

| Бібліотека | Версія | Звідки | Де | Для чого |
|---|---|---|---|---|
| `@supabase/supabase-js` | `2.119.0` | **своя** | усі сторінки сайту | акаунти, кошик, обране, замовлення |
| `@emailjs/browser` | `5.0.3` | **своя** | `checkout.html` | лист клієнту про замовлення |
| `decap-cms` | `3.15.1` | CDN | `admin/index.html` | сама адмінка |
| `jszip` | `3.10.1` | CDN | `admin/import.html` | масовий імпорт |
| `xlsx` | `0.18.5` | CDN | `admin/import.html` | читання Excel при імпорті |

Адмінські лишились на CDN свідомо: їх бачить лише власник, вони не
на шляху покупця, а `decap-cms` до того ж велика.

## Як оновлювати

Закріплення має зворотний бік: **оновлення тепер не приходять самі**,
у тому числі виправлення безпеки. Тому раз на кілька місяців варто
перевіряти версії свідомо.

1. Дивимо, що вийшло нового:
   - https://www.npmjs.com/package/@supabase/supabase-js
   - https://www.npmjs.com/package/decap-cms
   - https://www.npmjs.com/package/@emailjs/browser

2. Змінюємо версію **в одній бібліотеці за раз** — щоб при поломці
   було ясно, через що саме.

   Для своїх (`supabase-js`, `@emailjs/browser`):

   ```
   npm install --save-dev @supabase/supabase-js@НОВА
   npm run vendor
   ```

   Другий крок кладе нову збірку в `assets/js/vendor/`, прибирає
   стару й переписує теги на всіх сторінках. Для адмінських (CDN)
   правимо версію в адресі руками.

3. `npm test` локально, потім перевіряємо на сайті вручну те, що
   стосується цієї бібліотеки:

| Оновили | Що перевірити руками |
|---|---|
| `supabase-js` | вхід в акаунт, кошик після входу (кількість не зросла!), обране, оформлення замовлення |
| `decap-cms` | вхід в адмінку, редагування товару, публікація, прев'ю |
| `@emailjs/browser` | оформити тестове замовлення й переконатись, що лист прийшов |

4. Комітимо окремо, з версією в описі — щоб було що відкотити.

> Особливо уважно з `supabase-js`: саме там уже траплялась тиха зміна
> поведінки. Після оновлення обов'язково увійдіть в акаунт кілька
> разів підряд і оновіть сторінку — переконайтесь, що кількість
> товарів у кошику не змінюється сама.

## Dependabot

Відколи `supabase-js` і `@emailjs/browser` переїхали до себе, вони
оголошені в `package.json` — і **Dependabot їх бачить**. Це була
окрема вигода переїзду: доти вони були прямими посиланнями в HTML,
яких він не помічав, і стежити за ними доводилось руками.

Оновлення приходить звичайним PR. Після злиття обов'язково
`npm run vendor` і коміт — інакше в репозиторії лишиться стара збірка
бібліотеки, хоч `package.json` уже новий. Це ловить
`node scripts/vendor-libs.js --check`.

Три адмінські бібліотеки Dependabot і далі не бачить: вони підключені
посиланнями на CDN, тож за ними стежимо руками за переліком вище.
