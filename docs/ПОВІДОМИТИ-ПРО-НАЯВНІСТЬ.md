# «Повідомити, коли з'явиться»

Коли обраного кольору чи розміру немає на складі, сторінка товару показує
«Цей товар під замовлення». Тепер під цим блоком є поле пошти:

> Не хочете чекати? Напишемо, щойно ця річ з'явиться в наявності.

## Що відбувається

1. Людина лишає пошту → вам у Telegram приходить «🔔 Чекають на наявність»
   із назвою товару й варіантом (пошти там немає — лише що саме чекають).
   Це сигнал, що варто довезти.
2. Щогодини (Actions → **Stock alerts**) сайт звіряє підписки із залишками —
   тими самими, що бачить покупець, з урахуванням уже оформлених замовлень.
3. Щойно саме цей колір і розмір знову в наявності, людині йде **один** лист
   «Знову в наявності» мовою, якою вона підписувалась. Після нього підписка
   закрита.

Підписки, що чекають понад 180 днів, видаляються самі.

Товарам «📦 під замовлення ЗАВЖДИ» поле не показується: вони не
«з'являються» ніколи.

## Як увімкнути (один раз)

1. **Supabase → SQL Editor** → вставити `supabase/migrations/046-stock-alerts.sql` → **Run**.
   (Заодно варто виконати `045-buyer-request-issue.sql` — для форми байєр-сервісу.)
2. **Sync branches** (dev → main) — розклад GitHub бере лише з main.
3. Вставити новий `supabase/functions/telegram-order-bot/index.ts` у функцію.

Нових секретів не потрібно: розсилка бере ті самі, що й «Remind carts»
(`SUPABASE_SERVICE_ROLE_KEY`, `RESEND_API_KEY` або `BREVO_API_KEY`, `MAIL_FROM`).

## Як перевірити

- Actions → **Stock alerts** → **Run workflow**. У журналі видно
  «Підписок, що чекають: N» і «Уже в наявності: M».
- Без міграції 046 крок пише «Немає таблиці stock_alerts» і не червоніє.

Подивитись, на що є попит (SQL Editor):

```sql
select product_id, color, size, count(*)
  from public.stock_alerts
 where notified_at is null
 group by 1, 2, 3
 order by 4 desc;
```
