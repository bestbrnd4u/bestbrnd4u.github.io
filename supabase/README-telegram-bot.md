# Telegram-бот для заявок — як увімкнути

Бот надсилає вам у Telegram кожне нове замовлення з сайту і дозволяє
міняти його статус кнопками просто в чаті.

Усе безкоштовно: Supabase Edge Functions і Telegram Bot API вкладаються
у безкоштовні ліміти з великим запасом.

Часу на все — приблизно 20 хвилин.

---

## Крок 1. Створити бота

1. У Telegram знайдіть **@BotFather**, натисніть «Start».
2. Надішліть `/newbot`.
3. Введіть назву (як показуватиметься): наприклад `Bagvero Заявки`.
4. Введіть логін — має закінчуватись на `bot`: наприклад `bagvero_orders_bot`.
5. BotFather відповість токеном виду `12345678:AAH...`.

**Токен нікому не показуйте і не кладіть у код сайту.** Хто має токен —
може писати від імені бота й читати листування. Ми покладемо його
в секрети Supabase, куди має доступ лише ви.

---

## Крок 2. Дізнатися ID свого чату

Бот має знати, **куди** слати заявки. Це робиться зараз, до всього
іншого — функція для цього не потрібна.

1. Знайдіть свого бота за логіном і натисніть «Start».
2. Напишіть йому будь-яке повідомлення (хоч «привіт»).
3. Відкрийте в браузері, підставивши свій токен:

```
https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates
```

4. У відповіді знайдіть `"chat":{"id":123456789` — це число і є ваш
   chat_id. Запишіть його, знадобиться на наступному кроці.

### Якщо у відповідь прийшло `{"ok":true,"result":[]}`

Порожній `result` означає, що для бота немає непрочитаних оновлень.
Токен при цьому робочий — інакше була б помилка авторизації.
Причини за спаданням імовірності:

**1. Повідомлення боту не дійшло.** Перевірте, що писали саме тому
боту, якого створили (за логіном із BotFather). Напишіть ще раз і
одразу оновіть сторінку.

**2. Уже стоїть webhook.** Найчастіша неочевидна причина: якщо webhook
заданий, Telegram шле всі оновлення на нього, а `getUpdates` завжди
повертає порожньо — обидва способи одночасно не працюють. Перевірити:

```
https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo
```

Якщо `"url"` не порожній — зніміть webhook на час:

```
https://api.telegram.org/bot<ТОКЕН>/deleteWebhook
```

Далі напишіть боту й повторіть `getUpdates`. На кроці 6 поставимо
webhook назад.

**3. Повідомлення старше доби.** Telegram зберігає необроблені
оновлення близько 24 годин — просто напишіть боту заново.

### Найшвидший обхідний шлях

Напишіть боту **@userinfobot** — він одразу відповість вашим ID. Для
особистого листування з вашим ботом це те саме число, що потрібний
`chat_id`.

### Перевірити, що токен живий

```
https://api.telegram.org/bot<ТОКЕН>/getMe
```

Має повернутись логін і назва вашого бота.

Щоб отримувати заявки **в групу** (наприклад, разом із менеджером):
створіть групу, додайте бота, зробіть його адміністратором і напишіть
там повідомлення. Тоді `getUpdates` покаже id групи — він **зі знаком
мінус**, копіюйте разом із ним.

## Крок 3. Розгорнути функцію

У Supabase → **Edge Functions** → **Deploy a new function**.

Назва функції: `telegram-order-bot`

**Файл ОДИН.** Вставте в редактор вміст
`supabase/functions/telegram-order-bot/index.ts` — він самодостатній,
нічого доливати не треба. Натисніть **Deploy function**.

> Поруч у репозиторії лежать ще `format.js` і `_index.src.ts` — це
> **джерела**, з яких `index.ts` збирається автоматично. У панель їх
> вставляти не потрібно.
>
> Навіщо так: чиста логіка (текст картки, кнопки статусів) винесена в
> `format.js`, і саме на ній працюють 33 тести — напряму в Node, без
> імітації середовища Deno. Але деплой кількох файлів через панель
> легко зробити неповним, тож для деплою все зводиться в один файл.
> Перезібрати після правок: `node scripts/build-edge-function.js`
> (або просто `npm test` — він попередить, якщо збірка застаріла).

> Якщо користуєтесь Supabase CLI, з кореня репозиторію:
> `supabase functions deploy telegram-order-bot`
> (налаштування `verify_jwt = false` уже лежить у `supabase/config.toml`)

### ⚠️ Вимкніть перевірку JWT

**Без цього бот не працюватиме взагалі** — ні кнопки, ні сповіщення.

Edge Functions за замовчуванням вимагають JWT у заголовку
`Authorization`. Але цю функцію викликають дві сторони, і **жодна з
них JWT не надсилає**: Telegram (коли ви пишете боту чи тиснете
кнопку) і сама база (тригером при новому замовленні). Supabase
відхиляє такі запити ще до виконання коду, і бот просто мовчить.

У панелі: **Edge Functions** → натисніть на `telegram-order-bot` →
налаштування функції → вимкніть перевірку JWT. Перемикач називається
приблизно **«Verify JWT»** / «Enforce JWT verification» /
«Require authentication» — формулювання між версіями панелі різниться.

Безпека від цього не страждає: функція перевіряє власні секрети —
`TELEGRAM_WEBHOOK_SECRET` для запитів Telegram і `HOOK_SECRET` для
запитів бази. Запит без правильного секрета отримає 403.

## Крок 4. Додати секрети

Supabase → **Edge Functions** → **Secrets**.

⚠️ **Форма не приймає порожні значення** — заповніть усі чотири.

| Назва | Значення |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен із кроку 1 |
| `TELEGRAM_CHAT_ID` | число з кроку 2 |
| `HOOK_SECRET` | будь-який довгий випадковий рядок, вигадайте самі |
| `TELEGRAM_WEBHOOK_SECRET` | ще один випадковий рядок, **інший** |

Натисніть **Bulk save**.

`SUPABASE_URL` і `SUPABASE_SERVICE_ROLE_KEY` додавати **не потрібно** —
Supabase підставляє їх сам (вони видно в списку «Default secrets» нижче
на сторінці).

**Запишіть `TELEGRAM_WEBHOOK_SECRET`** — він знадобиться на кроці 6.

Два різні секрети потрібні тому, що функцію викликають дві різні
сторони: база (при новому замовленні) і Telegram (при натисканні
кнопки). Кожна підписує свій запит своїм секретом — без цього
будь-хто, хто дізнався б URL функції, міг би підробляти заявки
або міняти статуси.

## Крок 5. Налаштувати базу

Supabase → **SQL Editor** → **New query**.

Скопіюйте файл `supabase/migrations/001-guest-orders-and-telegram.sql`,
замініть у ньому два плейсхолдери:

- `<PROJECT_REF>` — ref проєкту (видно в URL панелі Supabase,
  щось на кшталт `hyfodsznpeeecgtgffub`)
- `<HOOK_SECRET>` — той самий рядок, що ви вписали в секрет `HOOK_SECRET`

Натисніть **Run**.

Цей скрипт заодно дозволяє зберігати **гостьові** замовлення. Раніше в
базу потрапляли лише замовлення авторизованих клієнтів, тож бот не
бачив би більшість заявок.

---

## Крок 6. Підключити Telegram до функції

Щоб працювали кнопки статусів, Telegram має знати адресу функції.

Відкрийте в браузері (підставте свої значення):

```
https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://<PROJECT_REF>.supabase.co/functions/v1/telegram-order-bot&secret_token=<TELEGRAM_WEBHOOK_SECRET>
```

У відповідь має прийти `{"ok":true,...}`.

> `<TELEGRAM_WEBHOOK_SECRET>` — той самий рядок, що ви вписали в секрет
> на кроці 4. Якщо вони не збігатимуться, кнопки під замовленнями не
> працюватимуть: функція відхилятиме запити Telegram як чужі.

## Крок 7. Перевірити

Оформіть тестове замовлення на сайті — у Telegram має прийти картка з
товарами, сумою і телефоном.

Або виконайте в SQL Editor тестову вставку — вона закоментована
в кінці файлу міграції.

---

## Як цим користуватись

Під кожним замовленням — кнопки. Натискання **одразу міняє статус у базі**
і перемальовує те саме повідомлення, тож у чаті завжди актуальний стан,
без дублів.

Ланцюжок статусів:

```
🆕 Нове → 👌 Взято в роботу → ✅ Підтверджено → 📦 Відправлено
                    ↓                ↓
               ❌ Скасовано     ❌ Скасовано
```

Кнопки показуються лише ті, у які має сенс переходити з поточного
статусу — «Відправлено» не з'явиться на скасованому замовленні.

## Якщо щось не працює

**Не приходять заявки.** Supabase → Edge Functions → Logs. Найчастіше:
не заповнений `TELEGRAM_CHAT_ID`, або в SQL лишився незамінений
`<PROJECT_REF>`.

**Бот мовчить на `/start`, кнопки не діють, сповіщення не приходять.**
Спершу подивіться `last_error_message`:
`https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo`

- `401 Unauthorized` — не вимкнена перевірка JWT (див. крок 3).
- `403 Forbidden` — секрет у `setWebhook` не збігається з
  `TELEGRAM_WEBHOOK_SECRET`. Виконайте `setWebhook` заново з правильним.
- `Read timeout expired` — Telegram дійшов до функції, але не дочекався
  відповіді. Найчастіше функція не стартує через помилку в модулі.
  Перевірте це так: **відкрийте URL функції в браузері** —
  `https://<PROJECT_REF>.supabase.co/functions/v1/telegram-order-bot`.
  На GET вона має віддати коротке `ok`. Якщо сторінка висить —
  функція не запускається, дивіться Logs; якщо `ok` — функція жива,
  і справа в обробці POST.
- порожньо, але й реакції немає — перевірте Supabase → Edge Functions →
  Logs: якщо викликів немає взагалі, запит не доходить до функції.

> Функція навмисно відповідає Telegram **одразу**, а роботу (запити до
> api.telegram.org і до бази) доробляє у фоні. Інакше при найменшій
> затримці Telegram рве з'єднання і ретраїть той самий апдейт — одне
> натискання кнопки оброблялось би кілька разів.

**Бот не відповідає на `/start`.** Це нормально до кроку 6 — доти він
просто не знає, куди слати відповіді.

## Що далі

Це перший рівень — сповіщення. Далі можна:

- **замовлення прямо в боті** — клієнт обирає товар і оформлює, не
  заходячи на сайт (зручно для трафіку з Instagram);
- **посилання з Instagram на конкретний товар** — `t.me/ваш_бот?start=product_15`
  відкриє бота одразу на потрібній моделі; такі посилання можна ставити
  в шапку профілю, сторіс і під Reels;
- **сповіщення клієнту** про зміну статусу і номер ТТН.
